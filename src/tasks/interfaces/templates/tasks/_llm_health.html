{# The navbar's LLM health dot. Its own `x-data` scope, separate from the page's. AGENTS.md's Alpine rule requires one top-level scope *per template* for the page's own interactions, and explicitly permits the layout to own scopes of its own -- the account dropdown beside this one already is one. Nesting them inside the page scope would instead mean every task page had to know about the nav's polling state. The dot is server-rendered in its unknown state and upgraded by `fetch`, so it never flashes a wrong colour: an amber "no idea yet" that settles into green or red is honest about what it knows at each moment. The endpoint is inlined into `x-init` from `url_for` rather than hardcoded, so the blueprint's URL prefix stays the single source of truth. #}
